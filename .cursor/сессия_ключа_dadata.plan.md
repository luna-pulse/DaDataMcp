# Сессия API-ключа DaData через форму в чате

## Что уже проверено

Оба ключа читаются в [`DaDataOptions.FromProcess`](src/DadataMcp.Server/Configuration/DaDataOptions.cs). Если ключа нет, процесс сейчас сразу завершается с ошибкой, ещё до того как Cursor успеет показать форму.

В HTTP уходит только `DADATA_API_KEY`: заголовок `Authorization: Token …` в [`DaDataClient`](src/DadataMcp.Server/Client/DaDataClient.cs). Три tool (`get_country`, `get_address`, `find_address_by_ip`) ходят в `suggestions.dadata.ru`. `DADATA_SECRET_KEY` ни в заголовок `X-Secret`, ни в тело запроса не попадает. Его удаляем из опций, сообщений и README.

Форма запрашивает один ключ — API-токен.

## Файл .env убираем

Токены и секреты в `.env` не хранятся. Рабочий файл [`.env`](.env) удаляется из каталога проекта. Образец [`.env.example`](.env.example) тоже удаляется: он больше не нужен. Загрузку `.env` и чтение `DADATA_API_KEY` / `DADATA_SECRET_KEY` из переменных окружения убираем из [`DaDataOptions.cs`](src/DadataMcp.Server/Configuration/DaDataOptions.cs). Содержимое `.env` в git не попадает (файл уже в `.gitignore`).

Единственный источник ключа — форма в чате. После отправки он лежит только в памяти процесса.

## Как ключ попадает в сессию

При включении MCP форма не открывается. Она открывается при вызове любого из трёх tools через метод `EnsureApiKey`, если сессия пустая или ей больше суток. Ожидание формы ограничено таймаутом (по умолчанию 3 минуты).

```mermaid
flowchart TD
    toolCall[Вызов одного из трех tools] --> gate[EnsureApiKey]
    gate --> alive{Сессия жива и младше суток}
    alive -->|да| ready[Ключ уже есть]
    alive -->|нет| form[Форма в чате Cursor]
    form -->|accept| memory[Положить в память сессии]
    form -->|decline или cancel| stop[Ключ не сохранён]
    ready --> call[Запрос в DaData только из tool]
    memory --> call
```

- `EnsureApiKey` — отдельный метод, не четвёртый MCP tool. Форму показывает Cursor по `elicitation/create` (`mode: form`) через `McpServer.ElicitAsync` из пакета `ModelContextProtocol` 2.2. Поле одно: строка API-ключа. Агент ключ в аргументы tool не передаёт и в чат его не просит — так ключ не попадает в логи tool и в промпт.
- «Передан с вашей стороны» и «со стороны агента» — это уже заполненная сессия после формы. Пока сессия пустая или протухла, форма открывается снова. Повторные вызовы в живой сессии форму не открывают.
- Хранение: singleton в памяти процесса. Ни файл, ни база, ни `.env`, ни переменные окружения. В stderr ключ не пишется.
- Срок: метка времени в сессии. Старше 24 часов — сессия сбрасывается, следующий tool снова спрашивает ключ. Новое включение MCP начинает процесс заново, память пустая, форма показывается снова.
- Отключение MCP в Cursor завершает процесс stdio. Память пропадает сама, отдельного «logout» нет.
- Если форму закрыли при вызове tool, вызов завершается коротким текстом ошибки, без запроса в DaData; следующий вызов откроет форму снова.

Клиент DaData перестаёт зашивать ключ в конструкторе. Заголовок `Authorization` ставится на каждый запрос из текущей сессии, чтобы после повторного ввода ушёл уже новый токен.

Спека MCP просит не собирать API-ключи формой `form`, а уводить на внешний URL. Для этой задачи берём форму в чате: ключ должен появиться в IDE, не в браузере, и не должен записываться на диск. URL-режим этому противоречит.

## Тесты

Автоматические тесты не пишем — ни в репозиторий, ни временные прогоны клиентом. Проверка сценариев только вручную в Cursor (см. раздел «Проверка после реализации»). Единственная автоматическая проверка — что проект собирается (`dotnet build`).

Проверка после реализации: собрать проект, убедиться что `.env` нет, включить MCP (форма не появляется), вызвать `get_country` и увидеть форму. Если форму закрыть и вызвать `get_country`, форма открывается снова. После ввода запрос проходит, повторный вызов форму не открывает. В логах stderr ключа нет.

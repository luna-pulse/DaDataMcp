# Фикс формы ключа DaData

## Проблема

MCP перестал открывать форму ввода `DADATA_API_KEY` (elicitation, `mode: form`) в чате Cursor.

## Причина (по коду)

Форма запрашивается из двух мест, оба идут через один `ApiKeyGate`:

1. `ApiKeyStartupService` показывает форму сразу после `notifications/initialized`, то есть при включении MCP.
2. Каждый из трёх tools (`get_country`, `get_address`, `find_address_by_ip`) вызывает `EnsureApiKeyAsync`.

В `ApiKeyGate.EnsureApiKeyAsync` вызов `server.ElicitAsync` идёт под семафором `_formLock`. При включении MCP чата ещё нет, Cursor может не показать форму и не ответить. У запроса нет таймаута, поэтому он висит и держит семафор. Вызов tool упирается в `_formLock.WaitAsync` и ждёт чужую форму, своей не показывает. Снаружи это выглядит как «MCP перестал спрашивать ключ».

Гипотезу про поведение Cursor я не проверял на практике. Критерии проверки (шаг 0):

- **Подтверждена**, если после включения MCP в stderr есть строка «запрос формы» для стартовой формы, но нет ни «ответ получен», ни «ключ при включении не введён», ни «форма закрыта без ключа», а вызов tool после этого завис на «ожидание семафора».
- **Опровергнута**, если стартовая форма завершилась (ответ получен или закрыта), а вызов tool всё равно не показал форму. Тогда причина в другом (например, Cursor не отправляет elicitation из tool или не заявляет `ClientCapabilities.Elicitation`), и шаги 1–2 нужно пересмотреть до правок кода.

Важно: удаление стартовой формы само по себе не гарантирует исправления. Если Cursor не отвечает на elicitation вообще, форма из tool тоже может зависнуть. Поэтому в план добавлен таймаут (шаг 2).

## Решения

| Вопрос | Решение |
|---|---|
| Форма при включении MCP | Не показывать, игнорировать |
| Форма при вызове tool | Обязательна, если в сессии нет живого ключа |
| Продление сессии | Оставить как сейчас: если до конца осталось не больше часа, вызов tool сдвигает срок на 24 часа от текущего момента |
| Проверка срока 24 часа | Ленивая, при следующем обращении к ключу. Таймер не нужен |
| Таймаут формы | Ожидание ответа на `ElicitAsync` ограничено (по умолчанию 3 минуты). По таймауту вызов завершается короткой ошибкой, семафор освобождается |
| TTL и порог продления | Значения по умолчанию 24 часа, переопределяются параметром запуска или переменной окружения (сам ключ там не хранится). Нужно для проверки без пересборки |
| Пересборка | Выполняется пользователем перед каждой проверкой |

## Правила жизни сессии

Ключ живёт только в памяти процесса. Сессия сбрасывается:

- при новом процессе MCP (включение, перезапуск окна Cursor, повторный запуск сервера);
- при выключении и отключении MCP-сервера;
- по истечении 24 часов без продления;
- при ответе 401 от DaData;
- если форму закрыли без ключа, ключ не сохраняется.

## Шаги

### Шаг 0. Подтвердить причину

- Пересобрать проект, выключить и включить MCP, вызвать `get_country`.
- Снять строки `[api-key]` из Output → MCP.
- При необходимости добавить временные метки в stderr: «запрос формы», «ответ получен», «ожидание семафора». Ключ в лог не писать.

### Шаг 1. Убрать форму при включении MCP

- Удалить `src/DadataMcp.Server/Configuration/ApiKeyStartupService.cs`.
- Убрать `AddHostedService<ApiKeyStartupService>()` и поясняющий комментарий в `src/DadataMcp.Server/Program.cs`.
- Поправить комментарий про процесс в `Program.cs`: ключ спрашивается при первом вызове tool.

### Шаг 2. Форма при вызове tool

- В `ApiKeyGate.EnsureApiKeyAsync` форма остаётся для каждого tool, если нет живого ключа.
- Параллельные вызовы ждут одну форму. Пока она открыта, вторую не открываем.
- Ожидание семафора (`_formLock.WaitAsync`) принимает `CancellationToken` вызова и тот же лимит времени, чтобы вызов не висел вечно за чужой формой.
- `ElicitAsync` вызывается с linked `CancellationTokenSource` (токен вызова + таймаут формы). По таймауту ключ не сохраняется, возвращается короткая ошибка.
- Семафор освобождается в `finally` при отмене, таймауте и ошибке `ElicitAsync` (сейчас `Release` уже есть в `ApiKeyGate.cs`, сохранить).
- Если первый вызов получил ключ, ожидающие вызовы после получения семафора повторно проверяют сессию и форму не открывают.
- `decline` или `cancel` формы: ключ не сохраняется, вызов завершается короткой ошибкой, следующий вызов снова открывает форму.
- Проверку `ClientCapabilities.Elicitation` оставить: без поддержки elicitation возвращаем понятную ошибку и пишем в stderr.

### Шаг 3. Сброс при остановке

- Главная цель шага: процесс гарантированно завершается при закрытии stdin (EOF), тогда ключ исчезает вместе с ним. Это проверяется в первую очередь.
- Дополнительно вызывать `ApiKeySession.Clear()` при остановке хоста (`ApplicationStopping` или `StopAsync` подходящего сервиса). Это страховка для graceful shutdown, а не основной механизм.
- Проверить то же для Docker: `docker run -i --rm --init` (`.cursor/mcp.docker.json.example`).
- Нигде не должно быть кэша ключа на диске или в переменных окружения.

### Шаг 4. Документация

- Обновить `README.md`: форма при включении MCP больше не открывается, она открывается при первом вызове tool в новом процессе и при любом следующем вызове после сброса. Описать правила сброса и продление в последний час.
- Обновить `.cursor/сессия_ключа_dadata.plan.md`: убрать раздел про форму при включении и `notifications/initialized`.

### Шаг 5. Ручная проверка в Cursor

| Сценарий | Ожидание |
|---|---|
| Включение MCP | Форма не показывается, процесс остаётся работать |
| Первый вызов `get_country` в новом процессе | Форма «Введите API-ключ DaData» открывается |
| Закрыли форму | Вызов завершается ошибкой, повторный вызов снова открывает форму |
| Ввели ключ, повторный вызов | Форма не открывается, запрос проходит |
| Выключили и включили MCP | Ключ сброшен, следующий вызов показывает форму |
| Отключили сервер, запустили заново | То же |
| Перезапуск окна Cursor | То же |
| Два параллельных вызова tool без ключа | Открывается одна форма, второй вызов ждёт; после ввода ключа оба проходят без второй формы |
| Форма открыта и не отвечает дольше таймаута | Вызов завершается ошибкой по таймауту, следующий вызов снова открывает форму, семафор не заблокирован |
| Клиент без поддержки elicitation | Вызов завершается понятной ошибкой, в stderr есть пояснение |
| Прошло 24 часа без вызова в последний час (запуск с уменьшенным TTL через настройку, без пересборки) | Следующий вызов показывает форму |
| Вызов в последний час перед сроком | Срок продлён, форма не открывается |
| Неверный ключ, ответ 401 | Сессия сброшена, следующий вызов показывает форму |
| Docker-вариант | Все сценарии выше |
| Ключ в stderr | Не попадает |
